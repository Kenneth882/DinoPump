# Remaining MVP implementation tickets

Approved breakdown, published on October 2, 2026. These files are reference copies of the implementation plan; GitHub Issues contain the current status, discussion, and acceptance evidence. Update the corresponding reference copy when an issue's scope or blockers change.

Read the [complete project specification](../../../PROJECT_SPEC.md), the ticket's focused requirements, and [implementation milestone gates](../implementation.md) before implementing. Existing workspace tooling and placeholders are accounted for in the tickets.

**ACs means acceptance criteria.** An ID such as AC-03 links a ticket to a required behavior in [verification](../verification.md). Several tickets may contribute to one AC through engine, database, service, and browser validation. Listing an AC means it needs verification; it does not mean it already passes.

Each ticket is labeled `ready-for-agent` on GitHub. Start a ticket only after every listed blocker is closed. Initially, [#1](https://github.com/Kenneth882/DinoPump/issues/1) is the only unblocked ticket. Keep fresh implementation sessions focused on one ticket and use its validation plan.

## Delivery and validation

The first two tickets cover the remaining foundation/content work. Pure engine slices are independently verifiable at the engine boundary; player-facing slices include service/persistence, contracts, UI, and tests together. Dependencies reflect the paths that must join before a behavior works, so some independent work can proceed in parallel.

The full plan covers AC-01 through AC-18. A milestone is complete only after its required behavior is demonstrated and its gates pass. Engine-only checks, written checkboxes, empty test runs, and unrun checks do not establish full acceptance.
